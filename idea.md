### Project Requirements Summary

#### 1. Core Architecture & Storage

* **Local-First & Self-Contained:** High-performance, low-cost architecture designed to run locally or host cheaply.
* **Metadata & State Store:** **PocketBase** (embedded SQLite backend) handles application metadata, user settings, workspace states, vendor API configurations, and notebook history.
* **Raw Object Store:** **RustFS** (lightweight S3-compatible store in Rust) serves as the immutable data layer for uploaded JSON, CSV, logs, timeseries, and batch API dumps.
* **Analytical Engine:** **DuckDB** reads raw files directly from RustFS using `httpfs` / S3 extensions to perform fast, local-first SQL queries.

#### 2. Workspace & Notebook Model

* **Hierarchy:** `Workspace` $\rightarrow$ `Data Sources` $\rightarrow$ `Notebooks`.
* **Shared Data & Context:** All notebooks within a single workspace share the underlying DuckDB analytical engine, raw files, and persistent domain context.
* **Workspace Directory Structure:**
```text
/workspaces/{workspace_id}/
├── workspace.duckdb
├── memory/
│   ├── metadata_schema.json
│   ├── onboarding_context.md
│   └── user_notes.md
└── notebooks/{notebook_id}/
    ├── chat_history.json
    ├── execution.log
    └── generated_assets/

```



#### 3. Ingestion Pipeline

* **Multi-Format Uploads:** Browser-based UI file uploads (JSON, CSV, Parquet, OTEL logs, timeseries).
* **Batch Ingestion & Buckets:** Placeholders for batch API ingestion endpoints and cloud bucket pulling (S3/GCP).
* **Data Safety:** Raw incoming data is backed up immutably in RustFS before processing, allowing users to reset workspaces or re-analyze without re-uploading.

#### 4. Pi Agent & Onboarding Workflow

* **Single Coding Agent:** A Pi agent equipped with shell/CLI tools (`duckdb-cli`, `jq`, `grep`, Node runtime) operates directly within the workspace folder.
* **Automated Data Discovery:** Agent inspects new uploads using DuckDB summary queries to derive table schemas, data types, distinct values, and null ratios.
* **Context Persistence:**
* Auto-generates initial insights in `onboarding_context.md`.
* Asks targeted clarifying questions during onboarding.
* Persists domain answers and uploaded reference files (`.md`, `.txt`) into markdown context chunks for ongoing memory.



#### 5. Dynamic Canvas & Dashboard Reports

* **Hybrid Visual Layer:** Combines a fixed set of React charting components (e.g., Recharts, Tremor) with freeform HTML/SVG generation for custom widgets.
* **Dashboard State:** Layouts (grid coordinates, KPI specs, widget configs) are stored as structured JSON specs in PocketBase.
* **Static Fallbacks:** Custom non-standard widgets generated by the agent are saved as SVG/HTML assets in `generated_assets/`.
